# P2P Lobby Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add an online P2P lobby (usernames, online player list, invite/accept, both launch the game) in front of the packaged Bedwars game.

**Architecture:** New static `index.html` lobby + `lobby.js` + `net.js` + `style.css` + original `assets/lobby/` art. Presence/invites/signaling over a free public MQTT broker; peer link over WebRTC (STUN). The packaged game moves to `game.html`.

**Tech Stack:** Vanilla JS, mqtt.js (vendored), native RTCPeerConnection, original SVG pixel art. Hosted on GitHub Pages.

**Spec:** `docs/specs/2026-09-23-p2p-lobby-design.md`

## Global Constraints

- No backend we own; GitHub Pages compatible (all static, relative paths).
- No gameplay sync — both players just launch `game.html`.
- Namespace all MQTT topics under `bedwars/v1/`.
- Original art only — do not copy existing costumes.
- Keep the existing game (`script.js`, `assets/`) untouched.
